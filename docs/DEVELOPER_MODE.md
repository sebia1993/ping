# F12 개발자 모드 사용 안내

## 1. 개발자 모드의 목적

개발자 모드는 사내에서 실행 파일을 시험한 뒤, 집에서 Codex에 전달할 수정 요청을 쉽게 만드는 기능입니다.
소스 코드가 없는 PC에서도 테스트한 프로그램 버전과 빌드 정보를 요청문에 넣을 수 있습니다.

개발자 모드는 요청문을 외부로 전송하지 않습니다. 요청문 생성, 마스킹, 클립보드 복사, 요청 기록 저장은
모두 현재 PC 안에서만 처리됩니다.

## 2. F12로 켜는 방법

1. 멀티핑체크 창을 한 번 클릭합니다.
2. 키보드에서 `F12`를 한 번 누릅니다.
3. 오른쪽에 개발자 패널이 열리고 `개발자 모드 켜짐 — F12로 종료`가 잠시 표시됩니다.

IP 입력칸에 커서가 있어도 F12가 동작합니다. 패널은 접거나 펼칠 수 있고, 좌우로 옮기거나 별도 창으로
분리할 수 있습니다.

## 3. F12로 끄는 방법

개발자 모드가 켜진 상태에서 `F12`를 다시 한 번 누릅니다. 패널, 선택 테두리, 개발자 ID 표시와 검사
이벤트가 즉시 꺼집니다. 개발자 패널의 닫기 버튼을 눌러도 같은 방식으로 종료됩니다.

프로그램을 새로 실행하면 개발자 모드는 항상 꺼진 상태로 시작합니다.

## 4. UI 요소 선택 방법

1. 개발자 패널의 `UI 검사` 탭을 엽니다.
2. `화면 요소 선택`이 체크되어 있는지 확인합니다.
3. 수정하려는 버튼, 입력칸, 문구 또는 그래프에 마우스를 올립니다.
4. 빨간 테두리와 개발자 ID를 확인한 뒤 클릭합니다.

검사 중 클릭은 원래 버튼 기능을 실행하지 않습니다. 버튼 안의 글자나 아이콘을 클릭해도 가능한 경우
버튼 전체가 선택됩니다. `Esc`를 누르면 현재 선택이 해제됩니다. `상위 요소`와 `하위 요소 선택`으로
화면 계층을 이동할 수 있습니다.

등록된 요소는 `main_dashboard.measurement.start_button` 같은 고정 ID를 표시합니다. 등록되지 않은 요소도
선택할 수 있으며 `개발자 ID: 미등록`과 임시 UI 경로가 표시됩니다.

## 5. 기능 선택 방법

`기능 요청` 탭에서 다음 방법 중 하나를 사용합니다.

- UI 검사에서 선택한 요소에 연결된 기능을 자동 선택합니다.
- 최근 실행 기능 목록에서 기능을 고릅니다.
- 기능 이름 또는 기능 ID로 검색합니다.
- 기능 ID를 직접 입력합니다.
- 목록에 없으면 수동 설명을 입력합니다.

프로그램 기능을 직접 실행해 최근 목록에 남기려면 `화면 요소 선택`을 끄거나 `기능 요청` 탭으로 이동한 뒤
기존 화면을 조작합니다. 최근 목록은 비밀번호나 입력값 원문을 기록하지 않습니다.

## 6. 최근 실행 기능 확인 방법

개발자 모드가 켜진 동안 실행한 등록 기능은 최근 20개까지 표시됩니다. 실행 시각, 성공 또는 실패 상태,
기능 ID를 확인할 수 있습니다. 같은 기능을 연속 실행하면 한 항목에 실행 횟수로 묶입니다.

항목을 두 번 클릭하거나 `기능 요청 대상으로`, `오류 대상으로` 버튼을 사용하면 해당 기능이 자동으로
선택됩니다.

## 7. 기능 변경 요청문 작성 방법

1. `기능 요청` 탭에서 요청 유형과 대상 기능을 고릅니다.
2. `원하는 변경`을 입력합니다. 이 항목만 입력해도 요청문을 만들 수 있습니다.
3. 필요한 경우 그대로 유지할 부분과 완료 기준을 입력합니다.
4. 현재 동작, 재현 순서, 변경 이유 같은 추가 내용은 `상세 입력 펼치기`에서 작성합니다.
5. `미리보기 생성`으로 내용을 확인하거나 `기능 변경 요청 복사`로 생성과 복사를 함께 수행합니다.

확인할 수 없는 코드 정보는 추측하지 않고 `확인 불가`로 표시됩니다.

## 8. 오류 수정 요청문 작성 방법

1. `오류 보고` 탭에서 대상 기능과 오류 화면을 선택합니다.
2. 오류 전 작업, 재현 순서, 실제 결과와 기대 결과를 입력합니다.
3. 발생 빈도와 재현 가능 여부를 선택합니다.
4. `마지막 오류 정보 포함` 여부를 확인합니다.
5. `오류 수정 요청 복사`를 누릅니다.

개발자 모드가 확인한 마지막 오류의 시각, 종류, 메시지는 선택적으로 포함됩니다. 전체 로그는 자동으로
붙이지 않습니다.

## 9. UI 수정 요청문 작성 방법

1. `UI 검사` 탭에서 수정할 화면 요소를 클릭합니다.
2. 개발자 ID, 종류, 크기, 위치와 코드 연결 정보를 확인합니다.
3. 원하는 변경을 입력합니다.
4. 기존 클릭 기능이나 주변 배치처럼 유지할 부분을 적습니다.
5. 완료 기준을 적고 `UI 수정 요청 복사`를 누릅니다.

## 10. 요청문을 클립보드에 복사하는 방법

다음 버튼을 사용할 수 있습니다.

- `UI 수정 요청 복사`
- `기능 변경 요청 복사`
- `오류 수정 요청 복사`
- `기술 정보만 복사`
- `개발자 ID만 복사`
- `기능 ID만 복사`

성공하면 `Codex 요청문이 클립보드에 복사되었습니다.`라고 표시됩니다. 복사에 실패해도 미리보기의 텍스트를
직접 선택해 복사할 수 있습니다. `Markdown 저장`을 누르면 UTF-8 형식의 `.md` 또는 `.txt` 파일로
저장할 수 있습니다.

## 11. 요청 기록을 다시 사용하는 방법

복사한 요청문은 `%LOCALAPPDATA%\MultiPingCheck\developer_requests.json`에 최대 50개까지 보관됩니다.
이 파일은 외부 서버로 전송되지 않습니다.

`요청 기록` 탭에서 기록을 선택한 뒤 다시 복사, 다시 편집 또는 삭제할 수 있습니다. `전체 기록 삭제`는
확인 후 모든 기록을 삭제합니다. 기존 프로그램 설정과 세션 파일은 건드리지 않습니다.

## 12. 회사 정보 마스킹 기능

`회사 정보 마스킹`은 항상 기본 ON으로 시작합니다. 요청문을 만들 때 내부 IP, 사내 도메인, 사용자 경로,
공유 경로와 식별 가능한 장비·서버 이름을 `INTERNAL_IP_01`, `DEVICE_01`, `USER_PATH` 같은 별칭으로
바꿉니다. 같은 요청문 안의 같은 값은 같은 별칭을 사용합니다.

비밀번호, 토큰, API 키, 쿠키, 인증 헤더와 세션 값은 회사 정보 마스킹 옵션을 꺼도 항상 제거됩니다.
마스킹 결과에는 원본 값 대신 항목별 처리 건수만 표시됩니다.

## 13. 로그와 스크린샷 포함 시 주의사항

`로그 포함`과 `현재 입력값 포함`은 기본 OFF입니다. 꼭 필요한 경우에만 켜고 미리보기에서 마스킹 결과를
확인합니다. 로그는 개발자 모드가 켜진 동안 수집한 최근 일부만 포함하며 전체 로그 파일을 넣지 않습니다.

스크린샷은 이미지 안의 비밀번호와 사내 정보를 확실히 제거하기 어려워 현재 버전에서 비활성화되어 있습니다.
민감정보가 제거된 화면 자료가 필요하면 회사 정책에 맞게 별도로 준비합니다.

## 14. 테스트 빌드의 Git 커밋 확인 방법

`기술 정보만 복사` 또는 생성된 요청문의 `테스트한 프로그램` 항목에서 다음 값을 확인합니다.

- 프로그램 버전
- 빌드 ID와 빌드 시각
- Git 커밋과 브랜치
- 소스 상태
- 배포 형태
- 설정 스키마 버전

Windows EXE 빌드 시 이 정보가 실행 파일 안에 저장됩니다. 사내 PC에 Git이나 소스 저장소가 없어도 값을
읽을 수 있습니다. 확인할 수 없는 빌드 환경의 값은 임의로 만들지 않고 `확인 불가`로 표시됩니다.

## 15. 개발자 모드가 정상적으로 꺼지지 않을 때

1. F12를 한 번만 다시 누릅니다.
2. 개발자 패널 오른쪽 위의 닫기 버튼을 누릅니다.
3. 그래도 남아 있으면 멀티핑체크를 정상 종료한 뒤 다시 실행합니다.

재실행한 프로그램은 개발자 모드가 꺼진 상태로 시작합니다. 문제가 반복되면 `기술 정보만 복사` 결과와
민감정보를 제거한 오류 내용을 함께 전달합니다.
